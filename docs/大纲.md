# 网站状态监测与日志收集系统（SiteSentry 哨兵）— 设计与大纲

> 版本 v1.0 ｜ 2026-09-04

---

## 一、市面通用系统调研

### 1. 网站状态监测类（可用性 / Uptime 监控）

| 系统 | 类型 | 特点 | 借鉴点 |
|---|---|---|---|
| **Uptime Kuma** | 开源自托管 | 最流行的开源监测工具：多协议探测(HTTP/TCP/Ping/DNS)、多通知渠道(邮件/企微/钉钉/Telegram…)、状态页、响应时间统计、SSL 到期提醒 | 目标管理+探测项设计、恢复通知、状态徽章 |
| **UptimeRobot** | SaaS | 5 分钟免费探测、邮件/SMTP 告警、SLA 报表 | 告警去重（故障期间不重复轰炸）、恢复通知 |
| **Healthchecks.io** | 开源自托管 | "死人开关"：外部任务定时上报 ping，超时即告警 | **外部上报令牌（token）** 机制 —— 其他网站向本系统汇报心跳/日志 |
| **Gatus** | 开源自托管 | YAML 配置、自带状态页、多种断言(status_code/latency/body_contains) | 断言式设计（期望状态码/关键词/响应时间阈值） |
| **Beszel** | 开源自托管 | Agent 模式，主机+容器资源与在线监测 | Agent/上报端思路 |
| **Prometheus + Alertmanager + Grafana** | 开源组合 | 指标采集+规则告警+可视化，生态最强 | 异常规则引擎（阈值/环比/持续次数）、通知收敛(inhibition/silence) |
| **夜莺 Nightingale / Zabbix / Nagios** | 开源 | 传统 APM/监控，探针多、告警链路成熟 | 告警分级、告警历史 |
| **Datadog / New Relic / CloudWatch / Checkly** | 商业 SaaS | 全链路 APM + 合成监测 + 日志 | **AI 功能**：Datadog Bits AI、New Relic AI 提供异常解释与诊断建议 —— 即本系统的 LLM 诊断方向 |

### 2. 日志收集类

| 系统 | 特点 | 借鉴点 |
|---|---|---|
| **ELK / EFK**（Elasticsearch+Logstash+Kibana） | 最主流日志栈，全文检索、可视化 | 日志级别(info/warn/error/fatal)、按来源/级别/关键字检索 |
| **Grafana Loki + Promtail** | 轻量日志聚合，标签检索 | "先采集后索引"、按标签(source)过滤 |
| **Graylog** | 开箱即用的日志平台，GELF 上报协议 | **HTTP 上报 API + token 鉴权** —— 外部站点 POST 日志的标准做法 |
| **Splunk / 阿里云 SLS / 腾讯云 CLS** | 商业日志服务 | 日志聚合告警（频率突增告警） |

### 3. 异常检测与 AI 诊断

- 传统方案：统计规则（阈值、3σ、EWMA 移动均值、环比突增、持续失败次数），Alertmanager/夜莺的规则引擎即此类。
- LLM 方案（本系统特色）：市面主流开源监测工具**均不带** LLM 诊断；商业 APM（Datadog Bits AI、New Relic AI、云厂商"智能运维助手"）开始提供"异常解释 + 修复建议"。
- 本系统落地两种 LLM 能力：
  1. **自动诊断**：异常产生时自动拼装上下文（探测结果、响应时间序列、最近日志、错误信息）调用 LLM，生成中文根因分析与修复建议，随告警邮件一起发出。
  2. **实时 AI 助手**：Web 端聊天面板，可询问系统内任何异常/日志，LLM 结合数据上下文回答。

### 4. 结论：本系统 = Uptime Kuma 的探测 + Healthchecks/Graylog 的 token 上报 + 规则引擎异常检测 + LLM 自动诊断 + 邮件告警，面向单个/多用户 Web 部署，**Go 单二进制**轻量自托管。

### 5. Go 后端框架选型

| 框架 | 特点 | 评价 |
|---|---|---|
| **Gin** ★选用 | Go 生态最流行的 Web 框架（50k+ star）：高性能、路由分组、中间件、JSON 绑定齐全，REST API 首选 | 生态最大、文档最全、够用 |
| Echo | 与 Gin 相近，API 略简洁 | 可选，无决定性优势 |
| Fiber | 基于 fasthttp，性能高 | API 与标准库略有差异，依赖偏多 |
| Chi | 标准库 mux 风格，极轻量 | 适合小服务，本系统端点多用 Gin 更高效 |
| Beego / Iris | 全家桶框架 | 偏重，本系统用不上 |

**选型：Gin** + go-sql-driver/mysql + golang.org/x/crypto(bcrypt)，共 3 个核心依赖，交叉编译为单二进制部署。

## 二、系统功能大纲

### 1. 用户与登录系统（完整）
- 注册 / 登录（密码哈希 password_hash + 登录失败锁定 + 会话管理）
- 角色：`admin`（首个注册用户自动成为 admin）/ `user`
- 管理员：用户管理（增删、改角色、禁用）、全局系统设置
- 普通用户：管理自己的监测目标、令牌、日志、告警
- 修改密码、个人资料
- 数据多租户隔离：所有业务数据按 user_id 隔离

### 2. 网站状态监测
- 监测目标：URL、期望状态码、期望包含关键词、请求超时、探测间隔(30s~1h)、通知邮箱、恢复通知开关
- 探测引擎：每分钟 cron 触发，探测到期目标 → 记录 状态/HTTP码/响应时间/错误详情
- 目标状态机：up / down / unknown；连续失败计数
- 历史与图表：最近 N 小时/天探测历史表 + 响应时间曲线（Chart.js）+ 可用率统计
- 手动"立即检查"、启用/停用、删除

### 3. 日志收集（收集其他网站的日志与异常上报）
- API 令牌：每用户可生成多个上报令牌（名称+token），供外部网站调用
- 上报接口（token 鉴权）：
  - `POST /api/v1/logs`：`{source, level, message, context{}}`
  - `POST /api/v1/anomalies`：`{source, title, severity, detail}`（外部站点主动上报异常，直接进异常队列并触发 LLM 诊断）
- Web 日志中心：级别/来源/关键字/时间范围筛选、分页、来源统计
- 内置上报示例文档（curl / JS / PHP / Python 代码片段）

### 4. 异常检测（规则引擎，每分钟评估）
- **监测失败**：目标 up→down 时生成异常（故障期间不重复告警，恢复时生成恢复通知）
- **响应时间突增**：最近一次响应 > 24h 均值 × 3 且 > 2s
- **日志错误爆发**：某来源最近 10 分钟 error/fatal 日志 > 阈值（默认 10 条，30 分钟冷却）
- **外部上报异常**：v1/anomalies 直接入库
- 异常字段：类型、严重级(critical/warning)、标题、详情、LLM 诊断结论、状态(未处理/已处理)、冷却去重

### 5. LLM 集成（OpenAI 兼容接口）
- 任意 OpenAI 兼容端点与模型（后台可配置，当前部署环境已验证可用）
- 异常自动诊断：结构化 Prompt（角色=网站故障诊断专家；输入=目标信息/探测历史/最近错误日志/错误详情；输出=根因分析+可能原因列表+修复建议，Markdown）
- AI 聊天助手：会话持久化，支持"附带上下文"提问（勾选最近的异常/日志一并送入）
- 配置可后台修改（key/端点/模型），含"测试连接"按钮

### 6. 邮件通知
- SMTP：支持任意 SMTP 服务器，SSL 465 / STARTTLS 587（自实现轻量 SMTP 客户端，无第三方依赖）
- 通知对象：目标级邮箱列表；默认全局邮箱（后台配置）
- 触发时机：故障、恢复、日志爆发、外部上报异常、手动测试邮件
- 邮件内容：HTML 模板，含异常详情 + LLM 诊断结论 + 系统链接
- **限速保护**（按飞书规则）：200 封/100s、单发件人 400 封/日 —— 超限自动进入待发队列，cron 到点重发；全部发送留审计日志(mail_log)
- 后台"发送测试邮件"验证链路

### 7. 仪表盘
- 概览卡片：目标在线数/总数、今日探测次数、未处理异常、今日 error 日志
- 最近 7 天可用率曲线、最近异常列表、日志级别分布

### 8. 系统设置（admin）
- LLM 配置（端点/key/模型/测试）、SMTP 配置（主机/端口/加密/发件人/授权码/测试）、全局默认通知邮箱、异常检测阈值

## 三、技术架构

```
浏览器 (Vue3 SPA + Chart.js + marked，原生 CSS)
   │
   ▼
Nginx (反向代理) ──proxy_pass──► Go 服务 127.0.0.1:33330 (Gin)
                                          ├── internal/api        路由/鉴权/各模块 Handler
                                          ├── internal/auth       用户/会话/上报令牌
                                          ├── internal/mailer     SMTP 客户端+限速队列
                                          ├── internal/llm        OpenAI 兼容调用
                                          ├── internal/monitor    探测引擎
                                          ├── internal/detector   异常规则引擎
                                          └── scheduler           进程内定时器(30s tick: 探测/检测/诊断/发信/清理)
MySQL 5.7+（数据库名可配置）           systemd: sentinel.service (开机自启/崩溃重启)
外部网站 ──► /api/v1/logs、/api/v1/anomalies（Bearer token 鉴权）
```

- 后端：**Go 1.27 + Gin**，交叉编译单二进制（本机 arm64 → linux/amd64，无 CGO），服务器无需 Go 工具链
- 依赖：gin-gonic/gin、go-sql-driver/mysql、golang.org/x/crypto
- 前端：Vue 3 + Chart.js + marked（vendor 文件本地化，无构建步骤），由 Go 直接提供静态服务
- 部署：Nginx 反向代理到 Go 服务；systemd 管理进程
